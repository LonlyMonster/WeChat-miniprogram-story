# 微信小程序首轮迁移 · 开发与验收计划

依据[登录与管理首页设计稿](../specs/2026-11-23-微信小程序登录与管理首页-design.md)及[已确认的账号菜单预览](../../ui/账号菜单预览.html)。首个交付点为同一小程序登录入口按身份进入各自首页，双方均可主动改密和退出。

| 顺序 | 开发交付 | 验收条件 |
| --- | --- | --- |
| 1 | 在现有 Node.js 后端扩展账户角色、最近登录时间及管理员初始化。迁移时保留内部用户编号与故事归属，旧账号默认家长。服务启动时自动创建管理员，默认密码为 `admin15@`，保留 admin 名称。 | 对已有故事的测试库执行迁移；原账号可读原书架。重复初始化保留当前密码，同名冲突明确报告。自助注册不能创建管理员。 |
| 2 | 为小程序提供登录、会话恢复、退出、主动改密接口；服务端核验当前角色。在一个事务内更新密码哈希并撤销该账号全部会话。兼容现有网页会话。 | 用家长和管理员分别登录，验证两台设备的会话；错误旧密码或取消操作不影响登录，有效修改后两端旧会话失效。家长调用管理接口被拒绝。 |
| 3 | 建立原生小程序客户端，接入共享登录页、家长书架和管理首页。启动时先验证会话，再重置页面栈。两端使用已定稿的账号菜单、右侧图标和改密表单。 | 测冷启动、返回、重新打开、过期及退出。admin 直接进管理首页，全程无家长书架请求。家长看到自己的书架。首次改密成功后用新密码登录，按原角色分流。 |
| 4 | 接通用户管理与模型配置。复用现有配置校验、密钥保护、版本冲突和审计逻辑，为小程序管理请求增加服务端角色鉴权。重置家庭用户密码采用一次性临时密码，单独处理强制改密。 | 确认和取消重置均测试；验证目标用户旧会话撤销、临时密码过期、重复使用和强制改密。配置可读写，错误值不覆盖旧值，已有 API Key 不回显。 |
| 5 | 将讲述、后台出图、命名保存和分页重读接入小程序。复用现有故事与任务接口，按当前账号和故事归属读取私有图片；页面切回前台时查询原任务。 | 真机用五格故事跨页测试，出图期间切回聊天再返回，原任务继续且不重复计费。核对手机单列、滑动边界、10 字标题、100 字正文和跨设备重读。 |

开发顺序为后端测试、开发者工具联调、微信真机回归。可并行准备小程序 AppID、开发者权限、测试用 HTTPS 域名及对应合法域名配置。部署若更换 Windows 服务账号或改用 Linux，需要在目标环境重新配置受保护的模型凭据。

首轮沿用已确认的家长端和账号菜单。用户列表、重置确认、临时密码展示及模型配置如需改变已有设计，在实现对应页面前核对差异。验收采用隔离账号及测试数据，先用可控任务验证重复提交与错误状态，再做真实出图验证。
